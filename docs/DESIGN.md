# SpamWatch design<br/><br/>SpamWatch is the product name; the repository, image and environment variables keep the name `outlook-junk-filter` (`OJF_*`).<br/>This document describes what is built as of **0.12.0**, how the parts fit together, and why they are built that way. For<br/>deploying and operating it, see the [runbook](RUNBOOK.md). For settings, see the [README](../README.md).<br/><br/>## Purpose and limits<br/><br/>One container instance watches the **Junk folder of one personal Microsoft mailbox** (`live.com`, `outlook.com`, `hotmail.com`)<br/>through Microsoft Graph. It scores every message it has not handled with SpamAssassin plus a few additions, and decides:<br/>keep, move to a quarantine folder, or delete. A small web page (the *review page*) lets a person see every decision, correct the<br/>filter's learning, restore mail, and manage the history.<br/><br/>Deliberate limits:<br/><br/>- **Junk folder only.** The Inbox and every other folder are never read. The job reads the quarantine folder only to expire old<br/>  messages.<br/>- **Nothing is changed until you say so.** The default mode is `report-only`: scores and would-be decisions are logged,<br/>  nothing is sent to Graph that changes mail.<br/>- **Any doubt keeps the message.** A fetch, scoring or action error, an invalid setting, or a missing setting never deletes.<br/>- **One instance, one mailbox.** There is no account field anywhere. A second mailbox is a second container with its own state.<br/>- **No message bodies are stored.** The log holds metadata, scores and rule names. Bodies are fetched again from Outlook when<br/>  something needs them (teaching, AI rating).<br/>- **amd64 image only.**<br/><br/>## Architecture<br/><br/>```mermaid<br/>flowchart LR<br/>  subgraph Container["outlook-junk-filter container (uid 1000, one process)"]<br/>    loop["Job loop (main thread)"]<br/>    ui["Review page + API (HTTP thread)"]<br/>    sa["spamassassin / sa-learn (subprocess)"]<br/>  end<br/>  graph["Microsoft Graph\n(Junk, Quarantined, Deleted Items)"]<br/>  ai["AI server (optional)\nOpenAI-style /v3 on the LAN"]<br/>  state[("/state: token, delta, bayes,\nlogs, status")]<br/>  cfg[("/config: local.cf,\nojf-allowlist.cf")]<br/>  browser["Browser / Homepage"]<br/>  loop -->|delta, raw MIME, move, delete| graph<br/>  loop --> sa<br/>  loop -->|rate in-range messages| ai<br/>  loop --> state<br/>  ui --> state<br/>  ui -->|re-fetch, move| graph<br/>  ui -->|sa-learn| sa<br/>  ui -->|allowlist lines| cfg<br/>  sa --> cfg<br/>  browser --> ui<br/>```<br/><br/>The job and the review page share **one process**: the page runs in a daemon thread started by the job, so they share the Graph<br/>client, the token cache (behind a lock) and the restored-messages list. If the page cannot start (port in use), the job logs an<br/>error and carries on. `python -m outlook_junk_filter.ui` serves the page alone, read-only, which the image tests use.<br/><br/>| Module | Role |<br/>| --- | --- |<br/>| `__main__.py` | Startup, the loop, sign-in, daily log prune, status file |<br/>| `config.py` | Reads and validates `OJF_*` settings; invalid values fall back to safe defaults and are reported as errors |<br/>| `auth.py` | MSAL public client, device-code flow, token cache in `/state/tokens/token.json` (mode 600), account address |<br/>| `graph.py` | Graph client: delta walk, raw MIME fetch, move, delete, folder lookup/creation, old-message query; retries and throttling |<br/>| `runner.py` | One scan pass: queue, per-message pipeline, decisions, quarantine expiry, run summary |<br/>| `scoring.py` | Runs `spamassassin`, parses its headers, reads Microsoft's SCL header, lints the config |<br/>| `ai.py` | Optional AI rating: text extraction, prompt, strict reply parsing, startup check |<br/>| `state.py`, `restored.py` | Delta link, retry list, handled ids; list of messages the user restored |<br/>| `logs.py` | Container log, `decisions.jsonl` (rotating), tombstones, pruning |<br/>| `status.py` | `/state/status.json`: account, version, mode, last scan time |<br/>| `healthcheck.py` | Container health: `/state/health` touched recently enough |<br/>| `ui/server.py` | HTTP routes, security headers, token and Origin checks |<br/>| `ui/pages.py` | All HTML (everything from the log is escaped) |<br/>| `ui/logreader.py` | Reads the logs: filter, sort, page, find, summary, what-if; hides deleted rows |<br/>| `ui/actions.py` | Teach, restore, allowlist, delete rows, batches |<br/>| `ui/history.py` | Reads `actions.jsonl` back for the *Actions taken* chips |<br/>| `ui/rules.py` | Plain-English rule descriptions |<br/>| `ui/stats.py` | Counts for `GET /api/stats` |<br/><br/>## The scan pass<br/><br/>Every `OJF_INTERVAL_SECONDS` (default 900, minimum 60):<br/><br/>1. **Lint** the SpamAssassin config. If it does not load, nothing is scored and every message is kept (an error is logged).<br/>2. **Token**: silent refresh. If there is none or it is invalid, start a device-code sign-in (see below) and wait for it.<br/>3. **Walk the Junk folder's delta query** (`/me/mailFolders/junkemail/messages/delta`). Pages are requested with<br/>   `Prefer: odata.maxpagesize=50`. (`$top` was used first and capped the walk at 50 messages; the header form pages correctly.)<br/>   A warning is logged if the first walk returns fewer messages than the folder reports.<br/>4. **Build the queue**: the retry list first, then new messages that are not already in the handled list (keyed by<br/>   `internetMessageId`, kept 90 days).<br/>5. **Per message** (see next section). State is saved every 25 messages.<br/>6. **Move the delta link on only after every message is handled or on the retry list**, so a crash replays the pass.<br/>7. **Expire the quarantine folder**: messages whose *received* time is older than `OJF_QUARANTINE_RETENTION_DAYS` are deleted<br/>   the way `OJF_DELETE_MODE` says (act mode only).<br/>8. Log a run summary, the AI and SCL counters, and write `last_scan` to the status file.<br/><br/>### Per-message pipeline<br/><br/>1. **Restored?** If the message's `internetMessageId` is on the restored list: keep (`restored`), never rescore.<br/>2. **Fetch** the raw MIME. A 404 means it left Junk; skip. Other errors: keep and retry (up to 3 attempts, then give up and<br/>   keep, logged as an error).<br/>3. **Score** with `spamassassin --nocreate-prefs --siteconfigpath /config` (no spamd). A scoring failure: keep and retry.<br/>4. **Microsoft SCL bonus**: the header `X-MS-Exchange-Organization-SCL` (present on Graph's copy) maps to points through<br/>   `OJF_MS_SCL_POINTS` (default `7=1.5, 8=3, 9=4`). The added rule is named `OJF_MS_SCL_<n>`.<br/>5. **Allowlist check**: any fired rule matching `OJF_KEEP_RULE_PATTERN` (default `^USER_IN_.*(WHITE|WELCOME)LIST`) means keep.<br/>6. **AI rating** (if configured, and not allowlisted, and the score so far is in range): may add points (see below).<br/>7. **Decide**, in this order:<br/>   - score ≥ `OJF_DELETE_THRESHOLD` → delete (`deleted-items` or `permanent`)<br/>   - else score ≥ `OJF_QUARANTINE_THRESHOLD` (quarantine on) → move to the quarantine folder<br/>   - else keep (`below threshold`, or `no threshold set`)<br/><br/>   In `report-only` the first two are logged as `would-delete` and `would-quarantine` and nothing is sent to Graph.<br/>8. **Record** one JSON line in `decisions.jsonl`, mark handled.<br/><br/>A Graph failure while acting (delete or move) keeps the message and retries it; a network failure aborts the pass and is retried<br/>on the next loop.<br/><br/>`act` mode behaves as `report-only` (with an error every run) when the delete mode is missing or invalid, when no threshold is<br/>set, when the quarantine threshold is not lower than the delete threshold, or when the quarantine folder name collides with a<br/>system folder.<br/><br/>## Scoring<br/><br/>### How SpamAssassin is run and configured<br/><br/>The job calls `spamassassin` as a subprocess per message with `--siteconfigpath /config`. That path *replaces* Debian's<br/>`/etc/spamassassin`, where the `.pre` files that load the plugins live, and without them nothing can be scored. So the<br/>Dockerfile copies the `.pre` files into SpamAssassin's *sys rules directory* (`/var/lib/spamassassin/<version>` after<br/>`sa-update`, else `/usr/share/spamassassin`), and the build fails if the Check plugin still cannot load.<br/><br/>The same directory receives `rules/ojf-rules.cf` as `99_ojf.cf`. Files in the sys rules directory load **before** `/config`, so<br/>`/config/local.cf` can override any shipped score (for example `score OJF_ED_SPAM 0`). (A `--cf` include loads *after*<br/>`/config` and cannot be overridden; the first attempt used it and was replaced for that reason.)<br/><br/>Rules are fixed when the image is built (`sa-update` runs at build time). Newer rules arrive with a new image.<br/><br/>### Shipped rules (`rules/ojf-rules.cf`)<br/><br/>| Rule | Score | What it catches |<br/>| --- | --- | --- |<br/>| `OJF_ED_SPAM` | +3.0 | Erectile-dysfunction pitches that avoid drug names; needs two of three phrase groups (subject, effect, pitch) so a health newsletter scores nothing |<br/>| `OJF_WEIGHTLOSS_AD` | +2.5 | Weight-loss and GLP-1 advertising, counted only when Microsoft's SCL is 5 or higher (the topic alone is not spam) |<br/>| `OJF_JUNK_ADMITS_SPAM` | +1.5 | SCL 5 or higher and SpamAssassin's stock `ADMITS_SPAM` fires |<br/><br/>SCL gating exists because two of these are about *topics*; Microsoft's own verdict is the second opinion that keeps legitimate<br/>health mail clear. The phrase lists are hand-written and need new entries as wording changes.<br/><br/>### Safe Links<br/><br/>Microsoft rewrites links to `https://<region>.safelinks.protection.outlook.com/?url=<target>`. SpamAssassin's shipped<br/>redirector patterns unwrap `url=`, so URL blocklists see the real target (tested every build on a synthetic message). The rewrite<br/>changes the body after the sender signed it, so DKIM reports invalid even when Microsoft's own result was a pass; an allowlist<br/>entry for such a message therefore rests on SPF.<br/><br/>### Bayes<br/><br/>The Bayes database lives in `/state/bayes`. It scores only after 200 spam and 200 non-spam messages have been learned.<br/>SpamAssassin's `bayes_auto_learn` is on by default; teaching from the review page corrects what it gets wrong. Teaching refetches<br/>the message from Outlook and runs `sa-learn` (with its own locking); nothing edits the database directly.<br/><br/>### AI rating (optional, off until `OJF_AI_URL` is set)<br/><br/>- **Where it sits:** after SpamAssassin, the SCL bonus and the shipped rules, before the decision.<br/>- **Which messages:** those not allowlisted whose score is in `[OJF_AI_MIN_SCORE, OJF_AI_MAX_SCORE)`; the upper bound defaults to<br/>  the delete threshold, because a message at or above it is already decided. The range keeps the slow model on the ambiguous middle.<br/>- **What is sent:** sender address, subject and the first 1,500 characters of text, to the server you configure. No headers or<br/>  attachments.<br/>- **Prompt injection:** the prompt marks the message as untrusted data and forbids following it; only a number in a strict JSON<br/>  reply is used, clamped to 0–10. A message that says "rate me 0" can at worst earn no points.<br/>- **Points:** `OJF_AI_MAX_POINTS × max(0, rating − 5) / 5`, so ratings of 5 or less add nothing and 10 adds the maximum. The rule<br/>  `OJF_AI_<n>` is added; `ai_score` and `ai_reason` are logged.<br/>- **Failure is harmless:** an unreachable server or HTTP error adds no points and stops further requests for the rest of the run<br/>  (one warning); an unreadable reply costs only that message.<br/>- **Startup check:** the job validates the address (a malformed `OJF_AI_URL` such as `host::8000` is an error and turns AI off) and<br/>  asks `/models` once, logging whether the model is available.<br/>- **The server:** the `ovms-npu` image (`npu-server/`) is OpenVINO Model Server with Intel's NPU driver 1.38.0 swapped in<br/>  (the stock image's 1.35.0 fails against 1.38.0 host firmware). It serves `OpenVINO/Qwen3-8B-int4-cw-ov`, one request at a time<br/>  (about 7 s each on a Meteor Lake NPU), no authentication, LAN only.<br/><br/>## Quarantine, restore and message ids<br/><br/>- Flagged messages move to a top-level folder (default `Quarantined`, created if missing; an existing folder of that name is<br/>  reused). The Junk-only scan never sees them again.<br/>- **Graph gives a moved message a new id.** The log therefore stores `current_message_id` and `folder` (where it is now); actions<br/>  from the review page use that id.<br/>- **Restore** (from quarantine or Deleted Items to Junk or the Inbox) adds the message's `internetMessageId` to<br/>  `/state/restored.json` (kept 365 days) so the next pass keeps it rather than rescoring and moving it back.<br/>- A permanently deleted message is gone: its row can be viewed, not taught or restored.<br/><br/>## The review page<br/><br/>Served by the job's process on `OJF_UI_PORT` (default 60888). **There is no login.** It is meant for a private network or<br/>behind a reverse proxy.<br/><br/>### Security model<br/><br/>- Everything from the log (senders, subjects, AI reasons, rule names, the mailbox address) is escaped; nothing builds markup by<br/>  concatenating a field. Subjects and senders come from phishing mail.<br/>- Content-Security-Policy: `default-src 'none'`; scripts, styles and images only from the page's own origin; no framing. The page<br/>  makes no external requests. Its script (`ui.js`) is a static file (select-all, selection bar, column resizing).<br/>- State changes are POSTs capped at 4 KB (256 KB for batches, 200 rows at most). With `OJF_UI_CSRF=on` each also needs the<br/>  per-process form token and a matching `Origin`. Off by default, because the page is for a private LAN.<br/>- CSV export prefixes cells that begin with `=`, `+`, `-` or `@`.<br/>- The page reads only `/state/logs/` and `/state/status.json`. It writes `actions.jsonl`, the tombstone file, the allowlist file<br/>  and the restored list, always through the job's own code paths.<br/>- `GET /api/stats` is open like everything else and returns counts only.<br/><br/>### Routes<br/><br/>| Route | Purpose |<br/>| --- | --- |<br/>| `GET /` | Decisions: filters, sort by any column, pager, selection bar, *Actions taken* column, score bubble |<br/>| `GET /message` | One record: every field, rules with descriptions, Actions panel with done/not-done indicators |<br/>| `GET /summary`, `/whatif`, `/export.csv` | Per-day counts, SCL table and histogram; threshold what-if; CSV of the filtered view |<br/>| `GET /confirm`, `POST /act` | Single action with a confirmation page |<br/>| `POST /batch` | Batch: first step shows the selection and the actions that fit; second step runs one |<br/>| `POST /delete-matching` | Delete every row a filter matches (recounts before deleting) |<br/>| `GET /api/stats` | JSON counts for Homepage, cached 30 s |<br/>| `GET /static/{style.css,ui.js,icon.svg}` | Assets |<br/><br/>### Actions<br/><br/>| Action | Effect | Recorded |<br/>| --- | --- | --- |<br/>| Teach spam / not spam | Re-fetch the message, `sa-learn --spam/--ham` | `actions.jsonl` |<br/>| Restore to Junk / Inbox | Graph move; add to the restored list | `actions.jsonl` |<br/>| Allowlist address / domain | Add `whitelist_auth <entry>` to `/config/ojf-allowlist.cf` (counts only when SPF or DKIM passes) | `actions.jsonl` (with the message id) |<br/>| Delete from log | Hide the row now; remove it from the files at the next prune. **Nothing in Outlook is touched** | `actions.jsonl` (one line per row, or one summary line above 200) |<br/><br/>In a batch, an action runs on the rows it fits and skips the rest with a reason; one failure does not stop the others; a message<br/>selected twice (or logged twice) is acted on once; allowlist entries are de-duplicated per sender or domain.<br/><br/>*Actions taken* chips are read from `actions.jsonl`. Teach and restore belong to the message id they were done under; an<br/>allowlist entry shows on every row from that sender.<br/><br/>### Plain-English rules<br/><br/>The bubble over a score and the message page describe fired rules in words. Sources, in order: a built-in phrase list for common<br/>rules (and `OJF_MS_SCL_n`, `OJF_AI_n`), then SpamAssassin's own `describe` text read from the rule files in the image, then the<br/>raw name. SpamAssassin's stock scores order the phrases (the log stores names, not points) and decide *Against it* versus<br/>*In its favor*; neutral rules are hidden from the bubble. At most five findings against and three in favor show, the rest counted.<br/><br/>### Logs, deletion and pruning<br/><br/>- `decisions.jsonl` rotates at 10 MB × 10 files. Each line is one scored message.<br/>- **Delete** appends `(message_id, ts)` to `/state/logs/deleted.jsonl`; the reader hides those rows immediately. The tombstone<br/>  file is written under a lock shared with the prune.<br/>- **Prune** runs in the job thread at startup and then every 24 hours, when nothing else is appending. It closes the log handler<br/>  (so no row goes to a replaced file), rewrites each file without rows older than `OJF_LOG_RETENTION_DAYS` (default 30; `0`<br/>  keeps all) or deleted by tombstone, removes emptied rotated files, trims old teach/restore/delete entries from<br/>  `actions.jsonl` (allowlist entries are kept so a sender's chip survives), and clears the tombstone file. A failure is logged and<br/>  never stops the job.<br/><br/>### Header, icon, status and stats<br/><br/>- The header shows the name, the **mailbox address** and an icon (also the tab icon, `/static/icon.svg`). The address comes from the<br/>  MSAL sign-in record, so no extra Microsoft permission is needed. The job stores it, with the version, mode and last-scan time, in<br/>  `/state/status.json`; the page and stats read it from there.<br/>- `GET /api/stats` returns `app`, `version`, `account`, `mode`, `healthy`, `last_scan_seconds_ago`, `today` and `last_7_days`<br/>  (`scored`, `kept`, `quarantined`, `deleted`, `errors`, `ai_rated`) and `log_records`. Counts use the latest record per<br/>  message in each window; "today" is the container's local day (`TZ`); report-only decisions count under their would-be class.<br/><br/>## State and files<br/><br/>| Path | Written by | Notes |<br/>| --- | --- | --- |<br/>| `/state/tokens/token.json` | auth | MSAL cache, mode 600, atomic replace. A key to the mailbox |<br/>| `/state/delta/state.json` | runner | Delta link, retry list, handled ids; atomic replace |<br/>| `/state/bayes/` | SpamAssassin, `sa-learn` | Own locking |<br/>| `/state/logs/decisions.jsonl*` | runner, prune | Rotating, pruned |<br/>| `/state/logs/actions.jsonl` | review page | Audit of page actions |<br/>| `/state/logs/deleted.jsonl` | review page | Tombstones, cleared by the prune |<br/>| `/state/restored.json` | review page | Restored messages, 365 days |<br/>| `/state/status.json` | job | Account, version, mode, last scan |<br/>| `/state/health` | job | Touched during work; health check reads its age (window: the larger of three intervals and 30 minutes) |<br/>| `/state/home`, `/state/tmp` | sa-learn, SpamAssassin | The container has no home directory; HOME and TMPDIR point here |<br/>| `/config/local.cf` | you | Never written by the job |<br/>| `/config/ojf-allowlist.cf` | review page | `whitelist_auth` lines; SpamAssassin loads every `.cf` in `/config` |<br/><br/>The container runs as uid/gid 1000 on a read-only root filesystem; only `/state` and `/config` are written.<br/><br/>## Sign-in<br/><br/>MSAL device-code flow against the `consumers` authority with the delegated scope `Mail.ReadWrite`. The Application (client) ID<br/>belongs to an app registration for *personal Microsoft accounts*, set as a public client. A client ID is only an app<br/>registration; each mailbox signs in separately and its token stays in that instance's `/state`. The job logs<br/>`SIGN-IN NEEDED: open <url> and enter code <code>`, waits for the code (touching the health file so the container stays<br/>healthy), and refreshes silently afterwards. A refresh failure that means the token is no longer valid starts a new sign-in.<br/><br/>## Failure behavior<br/><br/>| Situation | Result |<br/>| --- | --- |<br/>| Fetch, score or action fails for one message | Kept, retried (3 attempts), then kept for good; logged as an error row |<br/>| Network or Graph failure mid-pass | Pass skipped; delta link not advanced; retried next loop |<br/>| Process crash mid-pass | Pass replays; handled ids prevent double work |<br/>| Config invalid | Defaults applied, error logged; deletion never follows from invalid settings |<br/>| SpamAssassin config does not load | Nothing scored, everything kept |<br/>| AI server down or slow | No AI points; one warning per run |<br/>| Token expired | New device-code sign-in; scanning resumes after it |<br/>| Review page cannot start | Error logged; the job runs without it |<br/>| Prune fails | Logged; the job continues |<br/><br/>## Decision log<br/><br/>- **One instance, one mailbox.** Earlier versions had account slots; removing them removed a whole class of mix-ups. A second<br/>  mailbox is a second container (its own token, state, Bayes and allowlist), optionally sharing the app registration.<br/>- **`Prefer: odata.maxpagesize=50` instead of `$top`.** `$top` on the delta query stopped the walk at 50 messages.<br/>- **Subprocess SpamAssassin, no spamd.** Simpler and isolated; the cost (a process per message) is fine at personal volumes.<br/>- **Shipped rules in the sys rules directory.** So users can override a score in `/config/local.cf`.<br/>- **Microsoft's SCL as a score bonus and a gate.** The header is on Graph's copy of every message; it rescued obvious spam that<br/>  scored 1.2 and keeps topic rules from firing on legitimate mail.<br/>- **AI is ranged, additive and off by default.** It never decides alone; a failure cannot cause a deletion.<br/>- **Tombstones for deleting rows.** The job appends to the log while the page runs; rewriting from the page could lose a row. The<br/>  daily prune, in the writer's thread, does the real rewrite.<br/>- **No login on the review page.** Chosen for a private LAN behind a proxy. `OJF_UI_CSRF` adds token and Origin checks. The stats<br/>  endpoint follows the same rule and carries counts only.<br/>- **Plain-English rules from a curated list plus SpamAssassin's own text**, not from the AI: deterministic, instant and free.<br/>- **amd64 only**, built in CI; no local Docker needed or used.<br/><br/>## Testing, CI and release<br/><br/>- Unit tests (pytest) mock Graph and SpamAssassin and use synthetic `.eml` fixtures; ruff runs in CI.<br/>- `tests/image/test-image.sh` runs against the built image: SpamAssassin loads as an arbitrary non-root uid, fixtures score as<br/>  expected, Safe Links unwrap works offline, each shipped rule fires and stays quiet where it should (and can be overridden),<br/>  `sa-learn` writes Bayes on a read-only root, and the review page serves an escaped Decisions page with a CSP.<br/>- Release: bump `VERSION` in a reviewed PR; merging triggers the release workflow, which waits for approval in the `release`<br/>  Environment, then pushes `bdelima/outlook-junk-filter:<version>` and `:latest` (amd64), and creates the tag and GitHub<br/>  release last. Re-running a release for an existing tag is skipped unless forced.<br/>- The second image, `bdelima/ovms-npu`, has its own CI and publish workflows (`npu-server/VERSION`, tag `ovms-npu-<version>`).<br/><br/>### Version history<br/><br/>| Version | What changed |<br/>| --- | --- |<br/>| 0.1.0 | Repository scaffold |<br/>| 0.2.0 | Junk-folder scorer, image, tests and CI; first image release |<br/>| 0.3.0 | Quarantine folder with retention expiry; the review page (decisions, summary, what-if, CSV, teach, allowlist, restore) |<br/>| 0.3.1 | Fix: the delta walk stopped at 50 messages (page size now set with a `Prefer` header) |<br/>| 0.4.0 | One instance, one mailbox |<br/>| 0.5.0 | Microsoft SCL bonus |<br/>| 0.6.0 | Shipped rules: ED spam without drug names |<br/>| 0.7.0 | SCL-gated weight-loss and admits-spam rules; SCL view |<br/>| 0.8.0 – 0.8.1 | AI scoring; startup validation and model check |<br/>| 0.9.0 | Batch teach and restore |<br/>| 0.10.0 | Allowlist batches, *Actions taken*, plain-English rules, bubble, resizable columns, one-row toolbar |<br/>| 0.11.0 | SpamWatch header, icon and mailbox; delete rows; log pruning; stats API |<br/>| 0.12.0 | Delete all matching rows; batch actions return to the filtered view |<br/><br/>## Not built<br/><br/>Alerting beyond log lines and the health check; a login for the review page; moving wanted bulk mail out of Junk (only flagged<br/>messages move); Razor, Pyzor and DCC; a separate spamd container; scheduled rebuilds; shared learning between two instances<br/>(sharing a Bayes directory between containers is untested).<br/>
